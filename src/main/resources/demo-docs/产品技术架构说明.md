# AgentDesk 产品技术架构说明

## 一、产品定位

AgentDesk 是一个面向中小团队的企业知识库智能体工作台。用户上传制度文档、产品手册、会议纪要后，可以用自然语言提问，系统会先检索知识库，再由 Agent 调用工具、组织答案，并完整展示每一步推理过程。

## 二、技术栈

- 后端：Java 17、Spring Boot 3.3、MyBatis-Plus 3.5、MySQL 8.0、Spring Security + JWT、Caffeine
- 前端：Vue 3.5、TypeScript、Vite 5、Element Plus、Pinia、marked
- 文档解析：Apache PDFBox 3，支持 txt、md、pdf
- 接口文档：springdoc-openapi（Swagger UI）
- 构建与部署：Maven、npm，单 Jar 部署

## 三、核心链路

1. 文档入库：上传文件 → 解析文本 → 按句子边界切片（默认 420 字、重叠 80 字）→ 向量化 → 写入 MySQL。
2. 混合检索：查询向量与切片向量做余弦相似度计算，同时叠加关键词命中率，按 0.7 与 0.3 的权重加权排序。
3. Agent 推理：自研 ReAct 执行器，最多 5 轮工具调用，每轮记录 Thought、Action、Observation 与耗时。
4. 流式输出：通过 SSE 把推理步骤与答案分片实时推送到前端，首字节延迟低于 300 毫秒。

## 四、Agent 设计

Agent 执行器包含四个核心组件：工具注册表、Prompt 构造器、推理循环、轨迹记录器。内置工具包括知识库检索 knowledge_search、计算器 calculator、当前时间 current_time、知识库统计 knowledge_stats。新增工具只需实现 Tool 接口并注册为 Spring Bean，无需修改执行器。

为避免模型陷入死循环，执行器会检测连续两轮相同的工具调用并提前终止；工具异常会被捕获并作为 Observation 回填给模型，保证单次工具失败不会中断整个对话。

## 五、数据模型

核心表包括 users（用户）、documents（文档）、document_chunks（切片与向量）、conversations（会话）、messages（消息与推理轨迹）。所有业务查询都带 user_id 条件，保证多用户数据隔离。

## 六、演进方向

当前向量检索在应用内存中完成，适合万级切片；后续可平滑替换为 pgvector、Milvus 等向量数据库。异步文档解析可引入消息队列，把同步入库改为异步任务，提升大文件上传体验。
